## 第 1 页 · 项目封面（0:00–0:05）

**要点**

- 言行 SayDo Agent：面向家庭财务管理者的手机银行 AI 助手
- 将一句生活目标转为有授权、有进度的办理计划
- 言出即办，行必有据

**讲稿提示**：介绍作品名，随即说明服务对象，不展开技术名词。

**配图建议**：「妈妈生日准备」计划卡，底部小字「比赛原型 · 全部为模拟业务」。

## 第 2 页 · 用户与方法（0:05–0:30）

**要点**

- 服务对象：兼顾父母照料、家庭开支和纪念日的家庭财务管理者
- 痛点：同一目标的办理分散在多个入口
- 方法：一句话生成可修改、可追踪、按授权到期办理的计划
- 底线：模型提议，规则把关，用户掌握授权

**讲稿提示（约 80 字）**：前 30 秒介绍陈姐这样的家庭财务管理者：为父母转账、管开支、记纪念日。言行将一句生活目标拆成可修改、可追踪的办理计划；模型理解和规划，规则把关，用户授权后按时办理，改主意仍可继续。

**配图建议**：「陈姐」画像 +「父母生活费 / 家庭开支 / 妈妈生日」三个关键词，汇到一张计划卡；不编造访谈或用户增长数据。

## 第 3 页 · 痛点与监管（0:30–1:00）

**要点**

- 家庭事务横跨多个入口，用户自行安排顺序、记日期、留预算
- 资金操作需要准确金额、明确同意和可追查的结果
- 按 PRD 引用的高风险 AI 治理要求设计：分级、人工干预、紧急停用
- 目标：办成生活目标，让用户看懂并控制办理过程

**讲稿提示**：出处沿用 [PRD §9](01-产品需求文档-PRD.md) 的文件与条款；仅作设计依据，不代表已获监管认证。不使用未经测量的「转账必点 6–8 次」说法。背景到此结束。

**配图建议**：左侧「查账 → 留钱 → 买礼物 → 等日期」分散入口，右侧「目标 → 计划 → 授权 → 回执」。

## 第 4 页 · AI 的必要性（1:00–1:35）

**要点**

- 同一目标：「下周五妈妈生日，订花和蛋糕，再存 500」
- 传统办理：用户自行组织查账、存钱、商品和日期
- 言行：理解目标，生成有依赖的计划并追踪结果
- 改主意：保留已办部分，移除蛋糕步骤，到期按授权继续

| 同一个生日 / 定时购物目标 | 传统 App 的常见方式（设计对照） | 言行比赛原型 |
|---|---|---|
| 组织步骤 | 用户在多个菜单中衔接 | 一句话生成计划卡 |
| 途中变更 | 用户逐项检查、撤销或重办 |「蛋糕不要了」更新计划，已存款保留 |
| 日期与结果 | 自己记日期、查进度 | 临期询价；普通购物按授权到期付款，风险升高重新确认 |

**讲稿提示**：AI 将找入口转为组织目标：理解生活目标及变化、衔接步骤；规则模板负责可确定的部分。生日订单仍逐笔确认，普通购物可在确认计划时授权，不能概括为所有计划均自动付款。表格为设计对照，并非某家银行 App 的实测。

**配图建议**：同一句输入的两条流程，突出「改主意后继续」，避免只展示聊天外壳。

## 第 5 页 · 双平面架构（1:35–2:10）

**要点**

- 认知平面：AI 理解、规划、解释，仅输出提议
- 执行平面：规则把关，代码定级、确认、验证、记账与审计
- 写工具不向模型开放，执行必须持一次性令牌
- 工作流和模型共用策略引擎、确认卡与工具网关

**讲稿提示**：办理结果以核心账本和回执为准，模型声称「已完成」不算办结。用户受骗后主动确认、验证的风险仍存在，不说「任何情况下都转不走钱」。

**配图建议**：从 [架构图 §1](07-架构图.md#1-总体架构) 裁成两个平面，标出模型与写工具的权限边界。

## 第 6 页 · 代码模型分工（2:10–2:50）

**要点**

- 完整识别、参数齐全的固定请求由代码工作流处理；识别不全则交给模型
- 开放分析、多轮指代、复杂规划用模型；账务数字始终由代码算
- 比较卡片、统计口径、复现性和耗时
- 服务端处理时间与用户等待时间分别说明

| 11-01 冻结前复测：12 句 × 3 遍，GLM `glm-5.3-flash` | 确定性工作流 | 全部交给模型 |
|---|---|---|
| 卡片类型正确 | 36 / 36 | 32 / 36 |
| 区间、合计、笔数、口径一致 | 36 / 36 | 29 / 36 |
| 3 遍结果相同 | 12 / 12 | 9 / 12 |
| 平均响应 | 0.03 秒 | 11.49 秒 |

**讲稿提示**：来源为 [测试报告 §3.4](06-测试报告.md#34-确定性工作流-vs-全部交给模型)。10-31 同设计批次是 **0.02 秒 / 9.31 秒**，模型卡片 33 / 36；两批数据分别呈现。157 条回归整体平均 3.9 秒，需模型的 71 条平均 8.2 秒、最慢 21.6 秒，自由分析约 18 秒。页面有等待气泡和来源 / 耗时标签；尚无独立用户端延迟分布，不能将 0.02 秒称为所有问题的端到端耗时。

**配图建议**：两列来源标签 + 对比表；工作流 / 模型片段只放本页，不占视频主线。

## 第 7 页 · 六场景能力（2:50–3:10）

**要点**

- 六类场景能力支撑同一家庭目标，数量不代表创新
- 查询有来源，办理有确认，执行有回执
- 重点演示生日与支付，其余能力以表格说明覆盖范围

| 场景 | 已有能力 | 结果与限制 |
|---|---|---|
| 智能转账 | 称呼 / 姓名 / 手机号、同名澄清、协议与免密 | 逐笔确认，超额及其他风险升强验证 |
| 账单分析 | 月报、2024 / 2025 全年收支、逐月柱状图与同比 | 代码计算，消费与转账分口径 |
| 理财操作 | 本人测评、适当性过滤、申购 / 赎回 | 不代填问卷，不承诺保本收益 |
| 卡片管理 | 锁卡 / 挂失、限额调整、绑卡 / 解绑 | 主账户不能在线解绑；熔断不挡止损 |
| 订阅代扣 | 流水识别、续费提示、停止本行代扣 | 停代扣 ≠ 商户解约 |
| 跨场景联动 | 生日 / 普通日期购物、心愿罐、到期执行 | 商品、预算、来源有界，风险变化重确认 |

**讲稿提示**：不逐行朗读。六类能力支撑同一条链路，后续聚焦组织目标与授权。

**配图建议**：表格配六个图标，截图另放下一页，避免一场景一页。

## 第 9 页 · 跨场景计划（3:30–4:25）

**要点**

- 计划 DAG：步骤有依赖、状态可追踪，变更保留已办部分
- 到期执行：校验商品 / 预算 / 来源，普通购物按计划授权付款
- 资金保障：可先存罐锁预算，前一天不足提醒，到期不足「待补款」
- 模型计划未通过校验：整份丢弃，规则模板按用户原话重建，审计 `plan_rejected`
- 开放商品识别：未来日期购物不靠商品词表路由，指定商品不以其他商品替代

**讲稿提示**：本页聚焦可变更、有资金保障的跨场景计划创新。生日先存 500 → 去掉蛋糕 → 临期订花 199 → 罐余 301；「明天给我爸买一个1200元的按摩椅」生成两步计划，选中 1,099 元按摩椅，预算不等于成交价。问句、提醒不误判；无对应商品时如实说明，并列出可购类目。8 类模拟商城不等于全网可购。

普通购物确认计划时授权 🟡 到期付款，执行仍重算风险；补款后点「补款后继续」重询价，价格 / 配送等变化再确认，超过原送达日不付款。生日订单仍逐笔确认。主线按摩椅使用已开免密的 6688 活期卡可自动支付；若改为罐付款，1,099 元会按当前策略升 🔴，预算内仍可能需要验证。

**配图建议**：DAG「存罐 → 鲜花询价 → 订单」，蛋糕两步标「已移出计划」；下方「执行 / 待补款 / 过期」结果。旁注「模型计划被拒 → 模板重建」，规则模式录屏不冒充模型规划实测。

## 第 10 页 · 分级降摩擦（4:25–5:05）

**要点**

- 首次付款须先签《支付服务协议》，签后仍须确认原交易
- 本人选卡、点击金额弹出滚轮设额度，期限 30 / 90 / 180 / 365 天，可取消
- 开通 / 提额 / 换卡 / 延期需人脸 + 短信；额度内适用对象逐笔确认
- 新收款人、拆单、频繁交易、反诈、注入不豁免；解除关系后免密失效

**讲稿提示**：本人设置授权，以分级授权降低操作摩擦；免验证仍须逐笔确认。单笔设 2,000 / 每日 5,000 元。妈妈首笔 500 → 开通 → 妹妹 800 只确认 → 妈妈 2,001 升 🔴 并取消；第三张转账卡还叠加「5 分钟内转账频繁」，须同时说明超额与频繁转账两项原因。免密限默认卡与已验证亲密联系人 / 合作商户；仅 6688 主账户可付款。存罐人脸或短信任选，转回活期只确认；其他高风险仍双因子。

**配图建议**：协议 → 额度小窗 → 免密确认卡 → 超额原因，四格截图。

## 第 11 页 · 安全与权限（5:05–5:40）

**要点**

- 注入：输入检测、不可信文本隔离、参数来源校验
- 越权：模型无写工具与执行令牌，资金标识按来源核对
- 所见即所签：确认、验证、令牌绑定摘要，执行前再次定级
- 防幻觉：模板生成卡片，校验数字 / 已办理说法；自由分析进沙箱

**讲稿提示**：「提议 → 定级 → 确认 → 按策略验证 → 一次性令牌 → 网关 → 回执」。摘要绑定工具、参数、用户、nonce；令牌 60 秒且一次性。防幻觉仅在本页简述。沙箱为子进程与静态 / 运行时限制，不说容器级隔离。

**配图建议**：[写操作链路](07-架构图.md#2-写操作安全链路) 精简图 + 来源不符 / 摘要或风险变化的失败出口，截一张带原因的 🔴 卡。

## 第 12 页 · 熔断审计闭环（5:40–6:05）

**要点**

- 陌生转入 0.01 元夹带指令，备注不能变成授权
- 60 分钟内 3 次疑似绕过验证，转人工核实
- 资金与账户变更暂停；查询、锁卡 / 挂失等止损仍可用
- 人工解除留痕，按 trace 回放，哈希链可校验

**讲稿提示**：模拟客服核对三条记录、确认本人、模拟人脸后解除熔断；后台也可人工处置。哈希链检测内部不一致，没有外部锚点，不能承诺完全控制存储后仍不可篡改。

**配图建议**：异常账单 → 熔断卡 → 模拟客服解除 → 后台回放，只保留关键画面。

## 第 15 页 · 总结与边界（7:00–8:00）

**要点**

- 价值：为家庭财务管理者组织目标，变更后仍可继续办理
- 方法：模型理解与规划，规则定级、本人授权、执行可追踪
- 边界：单用户无登录；认证、核心与商户均模拟；仅 6688 主账户可付款
- 不足：模型轮次约 10 秒；知识问答真实对话历史命中 **85 / 91（93%）**，仍有未命中
- 下一步：行内身份 / 活体 / 设备绑定、真实接口、流式等待、更强隔离与审计外部锚点

**讲稿提示**：重申目标、授权与结果的衔接。知识问答 93% 是 10-31 修复路由后的 GLM 历史结果；修复前 58 / 91（64%），只测检索曾为 91 / 91（100%），不是同一指标。本次未重跑真实模型，不能称为 main 最新对话表现。后台单口令、演示模式未设口令会开放；预算内不保证自动支付，用户受骗后主动确认仍无法保证拦截。
