## 2. 自动化测试

### 2.1 运行方式

```bash
cd apps/api && uv run pytest -q
```

测试使用临时数据库，模型路径用 `tests/conftest.py` 里的脚本化假模型（`fake`），不调用真实模型、不读 `.env` 里的密钥。`make test` 等价于上面的命令，`make redteam` 只跑 `tests/redteam/`。

### 3.4 确定性工作流 vs 全部交给模型

同一批账单问题（明细 8 句、支出总览 2 句、账单报告 2 句），工作流打开和关掉各问 3 遍。参照答案是工作流的结果：这些说法规则能完整识别，卡片上的数字由账务引擎按原话算出。

```bash
make workflow-vs-llm        # 或 cd apps/api && uv run python scripts/workflow_vs_llm.py 3
```

脚本用临时数据库、演示日期 2026-10-30、不连企业微信，需要已配置的真实模型（约 36 次调用）。

| 2026-10-31，GLM `glm-5.3-flash`，12 句 × 3 遍 | 确定性工作流 | 全部交给模型 |
|---|---|---|
| 卡片类型正确 | **36 / 36（100%）** | 33 / 36（92%） |
| 区间、合计、笔数、口径与账务引擎一致 | **36 / 36（100%）** | 29 / 36（81%） |
| 3 遍结果完全相同的问题 | **12 / 12（100%）** | 9 / 12（75%） |
| 平均响应 | **0.02 秒** | 9.31 秒 |
| 中位 / 最慢 | 0.01 秒 / 0.05 秒 | 9.54 秒 / 20.06 秒 |

模型和参照不一致的 7 次：

| 问题 | 模型的回答 | 应为 |
|---|---|---|
| 最近3个月花了哪些钱（3 次里 2 次） | 消费分类卡（只有汇总，没有明细） | 交易明细卡，近90天消费 269 笔，30,611.48 元 |
| 我这一个月的消费记录（3 次都是） | 按「本月」统计：2026年10月（截至30日）87 笔，11,949.72 元 | 按「近30天」：90 笔，12,019.20 元。这句本身有歧义，算口径不一致，不算答错 |
| 这个月交通花了多少（1 次） | 口径填成「支出」，本例合计相同 | 口径「消费」 |
| 我的支出总览（1 次） | 账单报告卡 | 消费分类卡 |

同一脚本每句 1 遍的复跑（同日）：工作流 12 / 12 全对，平均 0.01 秒；模型数字一致 9 / 12，平均 11.72 秒。另一处偏差是「最近3个月花了哪些钱」口径填成「支出」，合计 59,170.31 元（把转账、理财也算进去了），正确是消费 30,611.48 元。

结论：

- **速度**：工作流轮次比模型快两个数量级（0.02 秒 vs 9.3 秒），回归集平均从 10.6 秒降到约 4.2 秒 / 条主要靠它。
- **准确率**：模型的错误集中在「选哪个工具」「口径填什么」，数字本身都由账务引擎算，没有编造；工作流把这两步交给确定性规则，就不会选错。
- **确定性（置信度）**：工作流只接「整句话都认得全」的说法，认不全就交给模型，不存在猜对一半；同一句话每次结果一样，可复现、可审计。模型 3 遍里有 3 个问题前后答得不一样。
- **边界**：比较、趋势、平均、规则不认识的商户、两个同名收款人、「大额」这类要判断的说法，仍交给模型（`tests/test_workflow.py` 逐条覆盖）。
