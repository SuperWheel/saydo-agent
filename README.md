# 言行 SayDo Agent

「银行 AI 智能体」参赛作品。口号：言出即办，行必有据。

用户在手机银行里说一句话，言行就能查账、转账、管卡、买理财、停代扣，也能把「下周五我妈生日，帮我订束花和蛋糕」这类多步的事拆成计划逐步办好。

设计上的核心判断：**大模型只负责理解和提议，没有执行权**。风险等级由确定性的策略引擎计算，写操作必须由用户在确认卡上确认（🔴 还要强验证：一般是人脸 + 短信，小额且只因累计额度升级、存入心愿罐和绑定亲密关系时，人脸、短信任选一种；叠加注入等风险仍要两项），服务端签发一次性执行令牌后，工具网关才执行。模型被注入后仍可能提出错误动作；没有用户确认及所需验证、拿不到令牌就执行不了。用户被骗后自己确认、自己验证的情况拦不死，只能靠反诈 🔴、冷静期和风险提示把人拦一下（见安全自评）。

> 演示环境：全部为虚构数据，人脸、短信均为模拟验证，回执带「模拟回执」水印，与任何真实支付通道隔离。

> **比赛版本**：同步 main `4a9b3fc`，2026-11-01。赛程统一见 [开发计划](docs/03-开发计划.md)。模拟环境只有Ⅰ类借记卡主账户（尾号 6688）有付款账本，暂不支持用绑定进来的他行卡付款。

## 五大安全机制

对应 PRD §7.4 的 S-01 ~ S-05。逐条的实现位置、测试证据和残余风险见 [安全自评报告](docs/05-安全自评报告.md)。

| 编号 | 机制 | 做法 |
|---|---|---|
| S-01 | 幻觉防护 | 余额、确认内容、回执都由服务端按工具结果渲染成卡片，不经过模型；模型的文字逐个核对数字和「已办成」类说法，不通过就重写一次，再不通过就换成模板句（`app/agent/grounding.py`） |
| S-02 | 注入防御 | 输入检测（伪造系统消息、编码夹带、同形字、不可见字符）；模型看不到写工具；转账备注、商户名只进隔离模型；金额和收款人只能来自用户原话和银行主数据；带注入标记的动作一律 🔴 |
| S-03 | 操作审计 | 每轮对话按 trace 记录输入、意图、策略决策、确认、验证、令牌、执行、回复；哈希链只追加，改任何一条都能校验出来；运营后台按 trace 回放 |
| S-04 | 异常熔断 | 验证连续失败、注入、短时间多笔转出、越权工具调用、下游工具出错，分别触发会话只读 / 暂停办理 / 转人工 / 工具断路；提示里写明原因和申诉渠道；止损操作不受影响；后台有全局只读开关 |
| S-05 | 沙箱 | 模型写的分析代码先过 AST 白名单，再在一次性子进程里跑：空环境变量、临时空目录、CPU 2 秒、墙钟 5 秒、内存 256 MB、禁写文件和子进程，审计钩子拦截文件 / 网络操作；只读脱敏快照 |

## 按需用模型：确定性工作流与固定脚本

不是什么都交给大模型。规则能把整句话认全的固定流程走**确定性工作流**，不调模型：查余额、给家人转账、锁卡 / 挂失、单步存入心愿罐、心愿罐管理、账单报告（「收支统计 / 近一年的收支统计 / 统计一下收支 / 2025年收支汇总」）、支出总览、「近30天的消费记录」「上个月在美团花了多少」这类明细、订阅、理财。比较、趋势、规则不认识的商户、多轮指代、规划、自由分析才交给模型。账单数字、区间、演示流水和余额配平都由固定脚本计算，模型不参与算数。模型在同一轮重复调用同一查询、返回内容相同的卡片时只保留一张（忽略查询时间差异，确认卡不去重）。

同一批 12 个账单问题各问 3 遍（GLM `glm-5.3-flash`，2026-10-31，`make workflow-vs-llm`）：

| | 确定性工作流 | 全部交给模型 |
|---|---|---|
| 平均响应 | **0.02 秒** | 9.31 秒（最慢 20.06 秒） |
| 卡片类型正确 | **36 / 36** | 33 / 36 |
| 数字与账务引擎一致 | **36 / 36** | 29 / 36 |
| 3 遍结果完全相同 | **12 / 12** | 9 / 12 |

模型的错误都在「选哪个工具、口径怎么填」：把「最近3个月花了哪些钱」答成分类汇总，或把转账也算进消费（59,170.31 元，应为 30,611.48 元）。气泡下方的标签会写明这一轮是「确定性工作流 · 不调模型 · 0.02 秒」还是「AI 生成 · 9.3 秒」；「设置」→「模型」里可以关掉工作流现场对比。设计说明见 [技术文档 §4.6](docs/02-产品技术文档.md#46-确定性工作流与固定脚本按需用模型)。

## 快速开始

需要 [uv](https://docs.astral.sh/uv/)（会自动准备 Python 3.12+）和 Node.js 20+。从零安装的完整步骤和常见问题见 [部署说明](docs/04-部署说明.md)。

### 一键启动（推荐评委使用）

macOS 在访达里双击仓库根目录的 **`一键启动.command`**，Windows 双击 **`一键启动.bat`**，也可以在终端运行：

```bash
make demo
```

它会自动安装依赖、建好 `.env`、启动后端和前端、打开浏览器，并在窗口里打印两个地址：

- **电脑打开**：`http://127.0.0.1:5173`
- **手机打开**：`http://192.168.x.x:5173`（手机和电脑连同一个 Wi-Fi，或手机开热点、电脑连上）

默认设置：手机可访问；每次启动都是一份全新的临时演示数据（退出后删除，不动 `data/dev.db`）；演示日期 2026-10-30（演示脚本按这一天编排）；端口被占用时自动换下一个空闲端口。在窗口里按 Ctrl+C 或直接关掉窗口，前后端一起停止。

可选参数：`make demo ARGS="--keep-data"`（保留演示数据）、`--rules`（规则模式，不调大模型）、`--local`（只给本机用）、`--no-face`（跳过进入前人脸核身）、`--today`（用真实日期）。没填模型密钥时自动是规则模式，演示主线都能走通；要用大模型，在 App 的「设置」→「模型」里填密钥即可，立即生效。

### 手动启动（开发用）

```bash
make install
```

```bash
cp .env.example .env
```

```bash
make dev
```

`make dev` 同时启动后端（http://127.0.0.1:8000）和前端（http://127.0.0.1:5173）。浏览器打开 http://127.0.0.1:5173 ，点输入框上方的快捷语就能体验。前端同时对局域网开放：手机和电脑连同一网络，打开启动日志里 `Network:` 那行的地址（如 `http://192.168.x.x:5173`）就能在手机上用。

现场电脑演示可用 `make demo ARGS="--local"`；手机演示须设置 `ADMIN_PASSWORD`，但它只保护 `/admin/*`，不能保护 `/dev/*` 的重置和时间快进。公共网络部署边界见 [部署说明 §3.3](docs/04-部署说明.md#33-运营后台口令)。

本机旧版演示库缺少新列时，启动会自动按种子重建，等同「重置演示数据」。

### 模型配置

DeepSeek 和智谱 GLM 二选一，有两种配法：

1. **前端的「设置」→「模型」**：点页面右上角「设置」→「模型」（没配置模型时，点顶部的「未配置模型 · 去设置」也能进）。选 DeepSeek 或智谱 GLM、填密钥，可以先「测试连接」；点「保存并生效」后写入仓库根目录的 `.env`，立即生效，不用重启。密钥不回传前端，页面只显示尾号，也不写审计日志。
2. **手动编辑 `.env`**：`LLM_PROVIDER` 填 `deepseek` 或 `glm`，再填对应的 `DEEPSEEK_API_KEY` 或 `ZHIPUAI_API_KEY`。各项说明见 [部署说明 §3](docs/04-部署说明.md#3-env-配置)。

知识问答默认用关键词检索（BM25）。想让它听懂换了说法的问题，可以在「设置」→「知识检索」里接一个向量模型（推荐硅基流动 `Qwen/Qwen3-Embedding-8B`，填 API Key 后「保存并生效」，后台自动算好知识库向量）；接口出错或超时时自动退回关键词检索。也可以在 `.env` 里填 `EMBEDDING_PROVIDER=siliconflow` 和 `SILICONFLOW_API_KEY`，见 [部署说明 §3.6](docs/04-部署说明.md#36-知识库向量检索可选)。同一页还有「重排模型」卡片（推荐硅基流动 `Qwen/Qwen3-Reranker-4B`，复用同一个密钥）：把检索出的候选逐条打分再排序，换了说法的问题答得更准、超范围的问题拒答更稳。重排默认开启（有硅基流动密钥就生效，填 `RERANK_PROVIDER=off` 关闭），向量检索可选，见 [部署说明 §3.7](docs/04-部署说明.md#37-知识库重排模型默认开启)。原话没查到时，助手会让对话模型把问题换个书面说法再查一次（agentic 重查，默认开，可在同一页关掉）。

不填密钥、或在「设置」→「模型」里关掉「启用大模型」时走规则模式，页面顶部显示「未配置模型 · 去设置」，演示主链路照样能跑通。`.env` 已在 `.gitignore` 里，不要提交。

### 演示路径

**支付协议配置**：`PAYMENT_AGREEMENT_PRESIGNED` 默认 `false`，建库和 `/dev/seed` 不预签协议，第一次付款会出协议卡，同意后继续原交易；测试和评测脚本设为 `true`，保留原有主线。此开关只影响种子数据，修改后需重新建库或重置数据。演示要单独重现协议流程，可调用 `POST /dev/payment-agreement/reset`：撤回演示用户的协议和免密授权、清除邀请免打扰记录，保留现有账本；仅 `DEMO_MODE=true` 开放。

付款成功后可从回执下的邀请卡开通免密（「暂不开通」后 30 天不再弹），也可说「开通免密支付」亲自填表。开通、调高、换卡或延长到期日需 🔴 人脸 + 短信，调低、缩短到期日、关闭 🟡；新收款人、频繁转账、拆单、反诈、注入规则不豁免。首次签协议、免密开通与超额升级的操作安排见[演示视频脚本](docs/09-演示视频脚本.md)。

演示以「陈姐给妈妈过生日」为一条主线，串起查账、整理订阅、家庭转账、生日计划、风险处置和审计回放；输入、顺序与时间安排统一见 [09-演示视频脚本](docs/09-演示视频脚本.md)。

右上角「运营后台」可以按 trace 回放每一轮的决策链、校验哈希链、查看熔断记录并人工解除，还有「重置演示数据」按钮。运营后台口令是 `.env` 里的 `ADMIN_PASSWORD`（也可以在「设置」→「模型」页底部设置）：设了口令后，打开「运营后台」或「设置」→「模型」前会弹框要求输入，本标签页内记住；没设口令时，只有 `DEMO_MODE=true` 才开放。

5 分钟演示的完整脚本见 [演示视频脚本](docs/09-演示视频脚本.md)。

### 企业微信渠道（可选）

后端可以作为企业微信「智能机器人」接入，在企业微信里私聊机器人查余额、账单、卡片状态、订阅、理财持仓和业务规则。用的是**长连接模式**：后端主动连 `wss://openws.work.weixin.qq.com`，不需要公网 IP、回调地址和消息加解密，本机就能跑。不配置时这个渠道不启动，其他功能不受影响。

**渠道降权**：企业微信里只做只读查询。转账、AA、锁卡、申购赎回、取消订阅、订花订蛋糕等需要确认的操作，机器人不展示确认卡、不执行，只回复「这项操作需要在言行 App 内确认」和 App 链接，点开后原话自动带进 App 输入框；确认、强验证、执行仍然只在 App 里完成。群聊里不查账户信息，请用户私聊。

需要你做的（图文教程见 [企业微信配置教程](docs/10-企业微信配置教程.md)，页面里「设置」→「企业微信」也有同样的步骤和截图）：

1. 注册企业微信（个人也可以注册一个测试企业）：https://work.weixin.qq.com
2. 管理后台 →「智能专区」→「智能机器人」→「创建」→「新建机器人」，选 **API 模式**，连接方式选 **使用长连接**，复制 Bot ID，Secret 点「点击获取」后复制，保存。
3. 言行右上角「设置」→「企业微信」，粘贴 Bot ID 和 Secret，点「保存并连接」，状态变成「已连接」即可，不用重启（也可以直接写进 `.env` 的 `WECOM_BOT_ID`、`WECOM_BOT_SECRET` 后重启）。
4. 在企业微信通讯录里搜机器人名字，私聊「我还有多少钱」。
5. 想在手机上点链接回 App：手机和电脑连同一网络（最稳的是手机开热点、电脑连上），照常 `make dev` 启动；链接会自动用电脑当前的局域网地址。点链接打开 App 时，原话已经填进输入框，核对后点发送（链接只带 30 分钟有效的交接码，不带原话）。

默认直连企业微信、不走系统代理（开发机上的 SOCKS 代理会让连接失败）；必须走代理时设 `WECOM_PROXY`。

身份绑定（演示版）：企业微信里给机器人发消息的成员，首次来消息时自动绑定到演示用户（`WECOM_BIND_USER_ID`，默认 1 号「李明」）；`WECOM_ALLOWED_USERS` 可以限定只有哪些 userid 能用。真实环境应改为用户在 App 内登录后，经企业微信 OAuth 网页授权拿到 userid 再绑定，未绑定的账号只回「请先绑定」。各项配置见 [部署说明 §3.5](docs/04-部署说明.md#35-企业微信渠道可选)。

同一个机器人同一时间只能有一个长连接，新连接会把旧连接踢下线；被踢的后端会停止企业微信渠道（日志有提示），不会和新连接来回抢。`make eval-llm`、`make smoke-llm` 和知识问答评测在脚本里关掉了企业微信，不会抢演示后端的连接；不要同时开两个读同一份 `.env` 的后端。

## 已知限制

- 单用户演示：没有登录，固定使用演示用户「李明」。
- 沙箱是子进程隔离，不是容器隔离；生产环境应换成 gVisor / microVM。
- 不做语音、图片、对外 MCP，答辩只讲架构。IM 渠道只接了企业微信，而且只读；企业微信身份绑定是演示版（按配置自动绑定），真实环境应走 OAuth 绑定。
- 固定流程为毫秒级；11-01 历史回归集的模型轮次平均 8.2 秒、最慢 21.6 秒，整体平均 3.9 秒。详见测试报告 §6，均为服务端耗时，不含用户确认、验证和网络呈现时间。
